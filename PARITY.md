### `criteria.countif-over-a-range-holding-an-error`

```
=COUNTIF(A1:A3,">0")
```

Pinned from the M2 review and still unsettled. SUM propagates an error found
in its range; the conditional aggregates may instead skip a cell that cannot
satisfy the criterion, on the grounds that COUNTIF asks a question about each
cell rather than combining them. Nobody here can settle which without Excel in
front of them, so the case is excluded from the score and Gridline's current
answer is recorded below.

Candidates: 2 (skip the error cell), #DIV/0! (propagate it)

Gridline currently answers `#DIV/0!`.

### `criteria.approximate-lookup-on-unsorted-data`

```
=VLOOKUP(15,A1:B3,2,TRUE)
```

The second question pinned from M2. Excel's approximate match is a binary
search that assumes ascending order; on unsorted data the answer is a property
of the search path rather than of the data, and Microsoft documents the result
as unspecified. Gridline does a linear scan for the last key not greater than
the lookup value, which is well-defined but not necessarily what Excel
returns. Excluded from the score, recorded here so a future run on a machine
with Excel can settle it in one line.

Candidates: mid (linear scan for the last key not greater than 15), high (binary search that stops at the first row), #N/A (a binary search that walks off the range)

Gridline currently answers `mid`.
